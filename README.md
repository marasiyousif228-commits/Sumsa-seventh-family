# نظام إدارة أسرة الدفعة السابعة — SUMSA

مشروع Next.js + Supabase قابل للتطوير. الواجهة عربية RTL وLight Mode، ومتجاوبة مع الهاتف.

## ما يتضمنه هذا الإصدار
- واجهة جانبية وصفحات: الرئيسية، مهامي، التكليفات، الإنجازات، السكرتاريات، دليل الأعضاء، الهيكل، التقارير، الملف الشخصي، الإعدادات.
- تسجيل دخول بالبريد وكلمة المرور عبر Supabase Auth.
- قراءة البيانات من قاعدة مركزية، وتحديث حالة المهمة.
- إنشاء تكليف من رئيس الأسرة/الأمين العام/سكرتير السكرتارية.
- فلترة أعضاء قائمة الإسناد حسب السكرتارية المختارة.
- SQL لهيكل السكرتاريات والمكاتب والأعضاء والتكليفات وسياسات RLS.
- Edge Function أولية لتذكير البريد قبل الموعد وبعد تجاوزه.

## الإعداد
1. أنشئ مشروعاً في Supabase.
2. من SQL Editor شغّل `supabase/schema.sql` ثم اختيارياً `supabase/seed_structure.sql`.
3. أنشئ مستخدمي Auth من لوحة Supabase (Authentication > Users).
4. أنشئ لكل مستخدم صفاً في `public.profiles` بنفس UUID الخاص بمستخدم Auth. عيّن الدور والسكرتارية المناسبة. لا تضع service-role key في الواجهة.
5. انسخ `.env.example` إلى `.env.local` وضع Project URL وanon key.
6. شغّل:
   ```bash
   npm install
   npm run dev
   ```
7. افتح `http://localhost:3000`.

## إنشاء حسابات الأعضاء
في مرحلة الإطلاق، يجب أن ينشئ مسؤول النظام حساب Auth لكل عضو، ثم يضيف صف الملف الشخصي المرتبط به. لا يوجد تسجيل عام ذاتي حتى لا يستطيع أشخاص غير معتمدين الانضمام. يمكن إضافة شاشة إدارة مستخدمين محمية لاحقاً باستخدام Route Handler على الخادم وSupabase service role.

## الأدوار
- `president`: إشراف عام وإدارة كل السكرتاريات.
- `secretary_general`: متابعة إدارية وإدارة جميع التكليفات.
- `finance_secretary`: الدور معرف في قاعدة البيانات؛ صلاحيات الإدارة المالية التفصيلية تحتاج إضافة جداول/سياسات مالية قبل استخدامها.
- `secretary`: إنشاء وإدارة تكليفات سكرتاريته فقط.
- `member`: قراءة وتحديث مهامه المسندة إليه فقط.

## البريد الإلكتروني
1. أضف secrets لوظيفة Edge Function:
   - `RESEND_API_KEY`
   - `MAIL_FROM` (عنوان موثق لدى Resend)
   - `APP_BASE_URL`
2. انشر الوظيفة: `supabase functions deploy task-reminders`
3. فعّل استدعاءً مجدولاً يومياً باستخدام Supabase Cron/pg_cron أو Scheduler خارجي.
4. اختبر رسائل upcoming وoverdue على عناوين اختبار قبل الإطلاق.

## نقاط يجب استكمالها قبل الإنتاج
- إضافة شاشة إدارة المستخدمين وإنشاء الحسابات بأمان من الخادم.
- إكمال صلاحيات الأمين المالي ووحدة السجلات المالية.
- إضافة المكاتب الفرعية إلى نموذج التكليف بعد إنشاء مكاتب فعلية.
- تفعيل Supabase Realtime والاشتراكات الحية؛ النسخة الحالية تعيد تحميل البيانات بعد العمليات.
- إضافة سجل تدقيق Audit Log، رفع الصور إلى Storage، واختبارات آلية.
- مراجعة سياسات RLS واختبارها بحسابات منفصلة قبل إدخال بيانات الأعضاء.
- نشر Next.js على Vercel أو استضافة مناسبة وربط متغيرات البيئة.

## ملاحظة أمنية مهمة
هذا أساس تنفيذي أولي وليس إطلاقاً إنتاجياً معتمداً بعد. راجع SQL وسياسات RLS، وأضف اختبارات الصلاحيات، ولا تستخدم بيانات حقيقية قبل إكمال خطوات الإعداد والاختبار.
